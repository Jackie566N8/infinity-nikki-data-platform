# Step 3 · 衣橱与玩家偏好分析

网站新增“我的衣橱”和“玩家偏好”。个人数据与公开调查数据使用独立存储，计算在浏览器内完成；不连接游戏账户，也没有上传或上报接口。

## 1. 个人衣橱的统计口径

沿用 `miraland-notes-v1` 中的 `saved` 和 `owned` 对象 ID，不迁移、不覆盖现有收藏。两者不能混淆：收藏用于表达兴趣，拥有用于统计收集进度。

### 拥有与完成

1. 逐件标记的服装 ID 直接视为拥有。
2. 明确标记整套拥有，推导为拥有该**具体形态**在 `outfit_clothing` 中的全部已知部件；推导只在内存中发生，不写回逐件标记。
3. 原色标记不会推导进化、焕新或其他变体；取消整套标记会撤销它提供的推导，独立的逐件标记仍保留。
4. 已知部件全部拥有、且部件数大于 0，才算套装完成。缺少部件关系的套装不自动算完成，单列“部件关系待补充”。
5. 完成率 = 当前筛选中已完成套装数 / 当前筛选套装数。默认仅原色，也可选仅附加形态或全部形态。全部形态不能表述为独立套装总数。
6. 风格与类别覆盖率 = 当前范围内已拥有部件数 / 该风格或类别总部件数。部件按自身品质、主风格筛选，按 ID 去重，不按套装关系重复计数。
7. “只差一两件”只包含已开始收集、尚缺 1–2 件的套装。未开始的两件套不会进入此列表。
8. 目标套装选择独立于品质、风格筛选，便于持续跟踪。缺件名称、类别、历史获取方式及来源从现有图鉴读取；未收录的获取途径明确显示待补充。

衣橱页、详情内的拥有操作及跨标签页存储变更会同步刷新统计。浏览器拒绝持久保存时提示导出备份；本地数据丢失后无法从服务器恢复。导出的个人分析 CSV 只在用户点击时下载。

## 2. 公开资料收录范围

初始公开数据有 **14 项来源审查、4 份可分析投票，涉及 5 个套装家族**。不同帖子的问题、候选和人群不同，参与者也可能重复，因此不合并票数、不汇总为去重玩家人数、不发布跨调查总榜。

| 独立调查 | 公示 N | 原选项比例 | 本站指标 |
| --- | ---: | --- | --- |
| [龙猫喜爱选择](https://www.taptap.cn/moment/700147148997528787) | 62 | 龙 38.7%、猫 19.4%、双方 41.9% | 喜爱支持率 |
| [龙猫抽取意向](https://www.taptap.cn/moment/699902022945605493) | 231 | 龙 35.5%、猫 30.3%、双方 34.2% | 抽取意向支持率 |
| [三生因缘外观评价](https://www.taptap.cn/moment/698970646377400845) | 118 | 好看 87.3%、不喜欢 12.7% | 外观赞同比例 |
| [扇妖与鹿套选择](https://www.taptap.cn/moment/766621634256701289) | 253 | 扇 29.2%、鹿 34.4%、都不抽 9.1%、双方 27.3% | 抽取意向支持率 |

对应家族 ID：龙隐云墨间 `o10330`、缘缘长相念 `o10331`、三生因缘 `o10244`、万相渡浮生 `o10352`、九色亦尘心 `o10353`。映射结合原帖版本语境及本站已有昵称资料。原帖没有逐形态投票，部分还谈到进化意愿，因此这些记录标为 `form_scope=family`，**不声称是原色专属偏好**。

来源记录 `collected_at` 是本次读取公开资料的 UTC 时刻。部分页面仅通过搜索索引正文读取成功，`access_method=indexed_page` 会明确记录，不能把它当作实时刷新后的票数。两个来源只显示月日，`published_date=null`，保留原始显示文字；没有推测年份。具体检索覆盖和未录入原因见 [PREFERENCE-SOURCES.md](PREFERENCE-SOURCES.md)。

### 计算方式

- **支持率**：将明确支持某套装的互斥选项比例相加。“都喜欢 / 都要”同时支持两个对象；支持率之和因此可能超过 100%。例如首份调查中龙套为 38.7 + 41.9 = 80.6%。
- 百分比按来源公示精度保存，整数票数未知时使用 `vote_count=null`，不根据四舍五入比例反推整数。
- 品质、风格筛选仅筛掉展示对象，**不改变原调查 N 或每项支持率**。
- 外观评价、抽取意向、喜爱投票彼此是不同指标，不能平均为“人气总分”。单套装评价只显示该对象，不能从一个对象推导榜单高低。
- **雷达图**：样本候选对象支持率按主风格汇总，再除以这些候选的支持率总和，得到“样本支持分布”。这不是全体玩家平均偏好；同时保留个人全部收藏分布作为背景，真正比较只使用本调查候选范围内的个人收藏。
- 家族调查的收藏按家族去重，收藏原色和进化不会重复计数；原色调查只比较原色收藏，具体形态调查按精确形态 ID 比较。
- 没有可比收藏时不绘制个人数据。未调查的风格标为“—”，不把未知填成 0。初始样本只覆盖少数风格，雷达图绘制有效轴上的点；只有五轴都有观测才形成完整多边形。
- **热门 / 小众参照**：与同一份调查候选套装支持率的算术平均比较，显示百分点差；这不是全体玩家平均评分。未覆盖的收藏明确标为无法判断。
- **推荐**：与个人收藏主风格相同、尚未收藏且未集齐、样本支持率不低于本调查候选均值。它是透明规则推荐，不是经过训练的预测模型，也不是抽卡或消费建议。
- **获取渠道**：使用原色家族的现有渠道标签，可重叠。数量为当前样本覆盖套装数；热度为这些对象支持率的均值。没有样本的渠道显示“—”，不能把商城一概称为充值。

## 3. 没有证据时不填图

### 跨版本风格趋势

目前没有同平台、同问题、同候选集合、调查时段明确的跨版本可比系列，页面显示“数据待录入”。已实现趋势计算和图表，后续研究需填写：

`comparison_series`、`comparability_note`、`period_start`、`period_end`、`period_version_id`。

只有至少两个正式可分析的时间点，且平台、指标、单位、样本范围描述、问题、形态口径和候选集合一致，才能成线。版本不得重复，调查时段不得重叠。未满足条件的记录不会被强行连线。纵轴是固定候选集合内各主风格的平均支持率；观察变化不证明因果关系。采集时间、本站快照时间、套装推出时间均不自动充当调查时段。

### 完成率与流水

当前没有对象与分母均可核验的逐套玩家完成率，也没有可核验的逐套官方收入。已提供输入与展示结构，暂不绘制虚构结果：

- `collection_rate`：整套持有人数 / 调查人数，不是单个玩家的部件完成比例。
- `mean_completion`：受访者逐人的部件完成比例的均值；必须明确调查对象是否包含未开始收集者。
- `revenue`：明确币种、观察区间、覆盖范围、对象归因规则的收入数值。第三方估计需如实标识，不能写成官方流水；平台总收入也不能硬分给套装。

这些指标使用 `observations`，每条为 `outfit_id`、`value`、`definition`。不得将 PV 播放、评论赞数、帖子浏览量、攻略评分或掉落概率代替上述指标。

## 4. 日常录入与维护

### 浏览器中的简单录入

1. 在“玩家偏好 → 来源、维护与历史 → 录入或更新公开数据”打开**双套装投票录入助手**。
2. 填写来源链接、平台、原问题、样本人数、范围、套装映射依据、更新说明；选择 A / B 套装。
3. 按原文填写仅 A、仅 B、双方、都不选的百分比；不存在的选项留空，不能用猜测代替未知。
4. 生成草稿并校验。页面显示合并后的来源和可分析研究数，**此时尚未保存**。
5. 点击“保存到本地公开资料”。更改仅存在本浏览器的公开资料存储中；整份更新与上一版会进入本地历史。
6. 单套评价、完成率、收入或有更多选项的研究，可下载 JSON 模板填写后导入，同样先校验预览。

同一来源 URL 应复用 `source_id`，相同研究沿用 `study_id` 更新。来源状态为 `pending` 时只用于待补充登记，不能进入分析；完成核验后才设为 `usable`，研究设为 `ready`。

本地公开数据使用 `miraland-public-preferences-v1`，与个人收藏键完全独立。公开数据导出不包含 `saved`、`owned` 或个人衣橱。历史导出用于存档；若浏览器存储配额不足，保存失败会提示，不会宣称成功或覆盖上一版。请定期导出。

### 更新交付网站

浏览器的本地录入不会自动修改发布文件。需要将“导出公开数据”的 JSON 放到源码的 `data/input/preferences.json`，然后在网站源码目录执行：

```sh
node update-quality.mjs
node scripts/platform/test-wardrobe.mjs
```

这会同时更新基础目录、质量、图鉴分析与公开偏好数据。单独构建公开数据可在 `data-platform` 目录执行：

```sh
node build-preferences.mjs
```

需要 Node.js 24 或以上，无额外依赖。单文件 HTML 的重新打包由项目工作区 `work/package.mjs` 完成；交付源码中的 `index.html` 可直接离线打开或静态托管。

### 校验与快照

- 检查 ID 唯一、来源 URL 去重、来源关联、套装 ID、原色/形态匹配、样本数、指标类型、单位、合法日期、选项映射、比例区间、总比例容差，以及已知票数与比例一致性。
- 录入不通过时不发布；构建之前也执行同一份校验。
- 内容散列标识快照；相同输入与目录快照不会重复建档。
- `dataset/preferences/history/` 保留不可覆盖的历史 JSON、父快照、完整前后变更和更新说明。
- 公共数据快照表示本站建档或更正，不代表新的调查波次；不能把重复采集同一投票的累计结果当作版本趋势。

## 5. 公开数据表

`dataset/preferences/community.sqlite` 是公开行为数据的独立数据库，避免混入个人衣橱。套装 ID 与 `miraland.sqlite` 一致，跨库关联由构建校验检查。

| 表 | 粒度与主要字段 |
| --- | --- |
| `public_sources` | 一个来源 URL；平台、采集时刻、样本量/范围、数据类型、可用状态、原始说明 |
| `studies` | 一份调查或观察期；指标、候选范围、问题、形态口径、样本量、时间区间、版本、对比系列 |
| `poll_options` | 一项互斥投票选项；名称、公示比例、已知票数或 NULL |
| `option_outfits` | 选项与支持对象的多对多关联；“双方”对应两个对象，“都不选”不对应对象 |
| `candidates` | 每份研究明确调查的候选套装 ID |
| `observations` | 套装级持有率、平均完成率、收入等有明确语义的观测值 |
| `public_snapshots` | 每次发布快照、生成时刻、父快照、修改说明 |
| `search_log` | 本次搜集的平台、查询词、结果与时间，包括未获得可核验数据的检索 |

`input/preferences.json` 是人工维护入口；`preferences-template.json` 是空白模板；`preferences-schema.cjs` 是网页与构建共享的校验规则；`wardrobe-model.cjs` 是网页与测试共用的计算模块。

## 6. 验证

`node test-wardrobe.mjs` 覆盖 54 组衣橱筛选、SQL 独立核对拥有推导、原色/进化隔离、缺件列表、家族去重、样本分母、推荐条件、趋势可比性、非法数据拒绝以及历史快照幂等性和不可覆盖性。测试中的模拟调查只用于临时目录或内存，不进入网站真实数据。

浏览器测试使用独立测试配置，覆盖源码和单文件版、标记同步、真实导出、录入预览及持久化、五种语言与五种屏幕宽度；不会修改用户当前浏览器的收藏。
