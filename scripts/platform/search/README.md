# 智能搜索评估框架 · Step 5

这是固定数据、固定查询和固定基准下的可复现实验。当前查询是有资料依据的 AI 辅助候选标注，**人工审核数为 0，不是人工审定 Gold Standard**。不能用“人工核对”的标签替代真正的人审。网站“搜索评估”提供逐条核对、修订和本地审核导出工作台。

## 查询集与划分

`dataset/search/queries.candidates.json` 共 100 条：90 个正例、10 个无答案例；六类为正式名、昵称、错字/拼音、不完整名、描述和多语言。查询由本站策划，不是实际用户日志。15 个有昵称来源的套装家族各 6 条，涵盖其正式名、部分关联部件、昵称、改写与外语；5 个无答案意图组各 2 条。首批描述仅使用已结构化、可核对的品质、风格、标签、服装图鉴及获取说明，没有从名称编造粉色、蝴蝶等视觉标签。

按家族/意图整组、固定种子划分 70:30：开发集 11 个正例家族 + 2 个无答案组，即 66+4 条；测试集 4 个正例家族 + 3 个无答案组，即 24+6 条。验证器检查 group_id 跨集、归一化重复查询跨集，以及任何相关答案所属家族跨集。不能将原色、进化、部件、昵称、跨语言改写拆成两个集合。

`dev.json` 用于改进，`test.json` 只在方法冻结后评测。标注者可以审核测试标签，模型开发者不能据此添加测试专用词典或调参。检索语料为网站内 8734 个套装/部件形态，ID 独立保留；不包括材料、妆容或祝福闪光。昵称默认以家族原色为正确答案，进化不能直接替代原色。无答案标签只限固定资料范围，不表示游戏永远没有该名称。例如“精灵颂歌”未在本次固定名称和昵称索引找到，作为待人工确认的范围边界例。

当前样本选择偏向既有昵称库，测试集只有 4 个正例家族，没有代表性抽样、真实频率加权或独立总体推断。扩展到无昵称套装、更多部件、歧义和视觉描述，需要新增资料依据、实际人审和新版本；不能以修正旧测试集错误来夸大泛化。

无答案例如果明确提到已知套装，也须与该套装家族处于同一集合：“1星生于无瑕”等矛盾约束与“生于无瑕”家族都在测试集。分组约束及验证器检查这种无答案上下文联系，即使 `expected_ids=[]` 也不能忽略。20 个原始组中存在这条上下文联系，不能将它们解释为 20 个完全独立抽样单位。

## 方法

`search-model.cjs` 同时用于 Node 和网页。A：归一化五语正式名的完全匹配；B：既有昵称完全匹配，沿用原有后缀与繁体形式；C：A、B 去重并集，正式名优先，套装原色优先，套装优先，稳定 ID 同分。归一化为 NFKC、转小写、去既有引号、去首尾空白，不做新拼音、错字、切词或语义处理。

现有网页不止精确搜索，还支持子串、翻译标签及获取字段；新增 L 单独模拟其默认全站规则，并与网页实际搜索在同一套装/部件语料范围核对。A/B/C 不冒充现有网页完整行为，生产搜索没有被替换成较严格的基准。

基准代码和语料、昵称、查询 SHA-256 在评测前锁定。`build-samples.mjs` 在现有版本相同时保留冻结结果，差异时拒绝覆盖。新算法要明确另存版本，不能偷偷更新锁或改测试标签。

## 指标

- Hit@1、Hit@5：有答案查询中第一条/前五是否有任何正确 ID。
- MRR：完整排名中第一个相关结果的倒数，未命中为 0；不截断到前五。
- 无答案识别率：仅无答案查询，空结果为正确。没有该类负例时返回 NULL/未评估，不能写成 0 或 100%。
- 平均响应时间：预热 5 轮，各查询/方法测 30 次，再对查询等权平均。报告所有查询和逐类型结果，单独保留索引构建耗时；不含网络、文件加载或 DOM 渲染。严格索引查表很短，接近计时噪声，不能凭微小延迟差断言速度优势。
- 额外给出有答案拒答率，避免把简单拒绝所有复杂问题所得的高无答案识别率解释为“理解能力强”。

`provisional/report.json`、`metrics.csv`、逐方法 `predictions-*.json` 和“基准评估报告.md”保留总体、开发/测试、逐类型指标、样本量、分母、耗时环境及预测 ID。没有人审时只发布 provisional，正式报告不产生。正式评测也不作未经独立样本支持的显著性结论。

## 复现与人工审核

需要 Node.js 24，无额外依赖。在网站源码根目录运行：

```text
node scripts/platform/search/test.mjs
node scripts/platform/search/evaluate.mjs --mode provisional
node scripts/platform/search/build-site.mjs
node update-quality.mjs
```

工作区中最后一项改为 `node src/update-quality.mjs`。重跑不会改方法或样本，时间测量会有设备噪声；数据和算法哈希固定。评估快照被冻结，不随当前网站版本自动替换。

真人逐条阅读查询、答案 ID、判定理由和资料链接；发现多解需追加全部可接受 ID，发现未知答案不能强记为空。工作台要求实际审核者标识，允许修改答案，记录审核时刻，并只保留在本地浏览器。导出 `miraland-search-human-reviews.json` 后：

```text
node scripts/platform/search/evaluate.mjs --mode official --reviews "C:/实际路径/miraland-search-human-reviews.json"
```

官方模式要求全部 100 条实际人审通过，拒绝空审核者、无效时刻、未知 ID、跨集答案家族和不同数据集的审核哈希。改完标签引入泄漏时须重新设计新版划分。人审标识是维护者记录，脚本不能鉴定真人身份；不得用自动填写姓名的文件冒充人审。

冻结数据已包含来源 URL、对象 ID、字段依据、查询语言、组与集合；`review-template.json` 是待审空状态模板。工作台本地审核不会自动改变当前展示分数，防止少量随意批准被当作已经完成的 Gold Standard。

## 后续研究方向

按开发集探索拼音、编辑距离、前缀与切词、结构化属性条件和语义候选；对“粉色、蝴蝶元素的裙子”一类视觉描述，先建立真实的颜色、部件类别与元素标注，不能从名称猜特征。冻结新方法后再运行独立测试。保留相同候选语料和相关性口径，分别衡量查询类型进步、错误拒答与错误匹配。
