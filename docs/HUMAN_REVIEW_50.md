## 怎么填写

先遮住预测列独立判断，再核对来源，确认查询真正相关对象的稳定 ID。原色、进化、部件分别判断，可有多个正确 ID。不得把 Top1 直接当答案。预测可见有诱导风险，不称为独立盲审。

JSON 每条 `query_id`、`query` 保持原样：

| 字段        | 填法                                                                       |
| ----------- | -------------------------------------------------------------------------- |
| status      | `approved` 已确认，`uncertain` 存疑，`pending` 未处理                      |
| correct_ids | 有答案写 ID 数组，例如 `["o10349"]`；无答案写 `[]`；存疑/未处理保留 `null` |
| answerable  | 有答案 `true`；无答案 `false`；存疑/未处理 `null`                          |
| reviewer    | 你的代号，不需要真实姓名                                                   |
| reviewed_at | 带时区，例如 `2026-10-13T20:00:00+08:00`                                   |
| evidence    | 实际来源 URL、游戏截图编号+面板位置，或已核查的目录范围                    |
| notes       | 判断理由；无答案必须写核查范围，存疑写缺少什么证据                         |

“无答案”是该网站快照无对应资料，不证明游戏中不存在；相似名字不能代替查询意图。存疑不计指标、不当零分。

完整保留 50 行，可以先审核一部分。回传已填 JSON，或已填写的 Markdown 表及证据信息；只有名称时，先映射稳定 ID，歧义项需你确认。不要更改快照与预测哈希。
