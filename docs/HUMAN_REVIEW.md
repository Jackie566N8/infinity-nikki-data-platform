## 原有两份表格

- [搜索 Gold 候选审核表](templates/HUMAN_GOLD_REVIEW.csv)：每个查询一行，包含当前答案 ID、可回答性、建议来源和审核状态。P0 为测试候选，P1 为开发候选；优先级不意味着测试标签用于调参。
- [数据审核清单](templates/DATA_REVIEW_CHECKLIST.csv)：配方、进化步骤、部件数量冲突和来源差异逐项列出，按 P0/P1/P2 排序。

复制模板后再填写，保存为不同文件名。自动构建会刷新空白候选模板，不能把你填写的表直接覆盖到模板文件。

审核搜索时，先独立判断查询是否有对应资料，再查看候选答案，避免仅确认现有标签。`approved_ids` 写 JSON 数组，例如 `["o10349"]`，无答案写 `[]`；`approved_answerable` 写 `true` 或 `false`。填 `review_status`（approved/rejected/pending）、审核人标识、带时区时间和证据链接。存疑保持 pending；发现标签不对可以纠正答案，同时写明理由。

录入后运行：

```text
node scripts/import-gold-review.mjs completed-review.csv
```

导入器要求真实审核元数据和证据；空模板不能生成 Gold。结果保存为本地文件 `data/review/human-reviews.local.json`，默认不提交 Git。部分审核不构成完整 Gold。不要修改冻结样本、开发/测试划分、模型权重或首次评估报告。若标签发生变化，应创建新的评估版本，检查家族泄漏，并另行运行和记录结果；旧报告必须保留。
