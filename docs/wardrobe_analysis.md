# 个人衣橱分析

## 问题、来源与方法

从浏览器本地“已拥有”标记计算套装完成率、风格/部位覆盖、只差1–2件的套装及目标缺件。收藏表示偏好，拥有表示收集，两者不互换、不发送服务器。

objects、outfits、clothing、outfit_clothing通过稳定ID连接。套装完成率=当前筛选范围完成数/范围内套装数；部位/风格覆盖=有效拥有的去重部件/对应范围内去重部件。原色与附加形态分开，分母0显示未评估。

整套拥有可推导其部件；来源成员数冲突时，逐部件拥有不能自动证明套装完整，用户整套标记单独计入。目标缺件=该形态去重成员−有效拥有，点击可查看部件获取方式。目标选择可独立于上方筛选，页面标明。

## 使用与验证

图鉴标记拥有→我的衣橱→品质/风格筛选→目标缺件。空衣橱显示0进度与真实缺件；file、localhost、Pages存储独立，备份导入/导出由用户主动操作。

运行 `node scripts/platform/test-wardrobe.mjs` 检查空输入、完成率、关系及样本边界。具体共享模型入口由 src/wardrobe.js 加载。

## 群体对比与限制

公开样本不是个人记录；雷达只比较样本覆盖的候选家族，未调查风格不补零。页面标注平台、样本量和时间，不称全体平均。成员来源冲突与收录遗漏限制完成率解释；不启动匿名搜索日志。
