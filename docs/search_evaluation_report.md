## 方法、指标与统计

A：正式名称完全匹配；B：昵称库匹配；C：A+B并集；D：归一化、拼音、前缀及编辑距离；E：来源支持的属性关键词匹配；F：冻结权重混合排序。A–F 使用相同的本轮语料和人审标签，原 F 的全部排序与 Step10 原始账本逐条核验一致。旧 8734 对象首次候选报告不覆盖、不改名成人审结果。

Hit@1/Hit@5/MRR 只以正例为分母；MRR 用完整排序中第一条正确答案的倒数，未命中为0。拒答率只以负例为分母；分母0显示 n.a.。单条多个正确 ID 取第一个相关结果。计时为3轮暖身、每查询20次，Node v24.19.0、win32/x64、AMD Ryzen 9 7945HX with Radeon Graphics        ；平均全部查询的模型响应，排除索引构建、网页、网络和导入耗时，不证明端到端用户体验。

## q063：失败原因与修复

“古典乐张”正确对象 `o10183`，原 F 返回空。实际库读音：输入 `gudianlezhang`，正式名 `gudianyuezhang`。错字改变了“乐”的语境读音，原拼音索引不相等。编辑距离1、四字相似度0.75，低于冻结门槛0.78，候选被过滤。空结果是此门槛与读音共同造成的漏检，不是目录缺对象。

修复作为 **F_v2 新版本**：仅在原 D/F 返回空且输入为3–18个汉字时，在真实中文名称索引里寻找仅一字不同且该字读音相同的候选。张/章同音且“古典乐章”确实存在，因此可纠正。没有全局替换姓氏“张”，没有降低0.78门槛；最多20个确定名称候选，原命中优先、E不增加模糊回退、外部品质/风格/类别仍硬过滤。回退给予0.96同音匹配信号（启发式分数，不是正确概率）并使用原排名公式。对非同音错字、多个错字、已有错误结果、超范围输入仍有局限。

修复后 q063 的 Top1 为 **o10183 古典乐章**，分数0.76，依据为“已收录名称单字同音：张→章”。原报告仍保留未命中，不以修复后结果覆盖原 F。

## 改进了多少与为什么

- 原 F → F_v2 整体 Hit@1/Hit@5：**97.73% → 100.00%（+2.27个百分点，增加1条开发正例）**；MRR 0.9773 → 1.0000。
- 错字/拼音：8/9 → 9/9（+11.11个百分点）；开发正例31/32 → 32/32（+3.125个百分点）。
- 测试12正例：前后都12/12，**测试增幅0**；负例前后6/6，未把漏检当拒答成功。
- 暖 F 平均 0.3136ms → 0.3201ms，差 0.006526ms；单次机器计时有噪声，微小差异不宣称稳定性能退化或提升，也未计新增索引内存/冷启动。

机制解释由复现的拼音/门槛与受控同音回退支持，**不是泛化因果证明**。q063 原本属于开发集，修复在观察此开发错误后完成；同一已公开测试仅作回归验证，不称新的未见测试。下一步需要自然查询、不同家族、新的独立留出集与多审核者/独立遮蔽预测审核；不能为本轮100%宣称稳定万能搜索。
