# 采集路线录入与精度边界

当前数据库有 **0 个精确采集坐标、0 个传送点、0 条通行边**。`data/routes/region-recommendation-input.json` 只整理已存在的区域对应关系。页面按材料缺口提供区域备选建议；没有路程、用时、最短路径或最优性保证。同一材料出现在多个区域，不意味着需要在每个区域重复补齐全部缺口。

## 录入流程

1. 使用游戏内地图/实测录像记录坐标。填 [节点模板](templates/ROUTE_NODES.csv)，同时注明坐标系、单位、地图版本、材料产量和采集条件。未知产量留空。
2. 实际走过两点之间的道路后，填 [通行边模板](templates/ROUTE_EDGES.csv)。记录路径折线、方向、时间、所需能力、地形和开放条件；跨区域边要有明确转场依据。
3. 将传送点作为独立节点。传送边明确解锁条件、时间和费用，不能用直线距离冒充步行道路。
4. 填 [路线步骤模板](templates/ROUTE_WAYPOINTS.csv)，保留来源、审核人和时间。未审核数据不得对用户宣称“精确路线”。
5. 需要计算时，将 CSV 转成 `{ "nodes": [...], "edges": [...] }` JSON。数字使用数值类型，`directed` 使用布尔类型，`polyline` 为坐标数组。运行 `node scripts/validate-route-data.mjs recorded-route.json`。该校验只检查结构和证据字段；不能代替游戏内实测，也不会自动启用网站路线功能。

路径资料齐全后，可以在同一坐标系和版本内使用 Dijkstra 求可通行最短路径，再对多个采集目标做带条件的访问顺序估计。仍需考虑刷新时间、产量不确定性、天气/时段、能力和传送限制。坐标齐全但没有通行边时，只能给出坐标级估计，并明确其精度。
