## 原因

原区域标题不是CSS背景图，而是 `app.js` 动态插入 `<img src="assets/hero.jpg">`。源目录该JPEG确实存在（1280×720、205615字节，可完整解码），九个区域却都共用它，未配置各区图片。

单文件打包器此前仅将PNG/SVG内嵌，漏掉JPEG。生成HTML放在outputs后，仍引用相对路径 `assets/hero.jpg`，该目录没有这张图。通用错误处理隐藏失败图片，但地图标题没有专用fallback，于是只剩紫色底色/遮罩。首页同一张JPEG也有相同问题。不是原图截断、CDN失效或这张本地图被gitignore排除。

## 修复

- 在 `src/assets/region-banners/` 管理九区主资源及九份原创SVG兜底，ASCII小写文件名、正斜杠，相对src/index.html引用。官网原图直接保存，保留版权与原字节；CSS负责视窗取景。
- 八个主资源为官网素材，纪念山地为原创主题插画，明确标注“官方图片待补”。石树田无人区使用官网 **Stonewoods合并地区图**，不冒称精确子区实景；小石树田村为官网区域活动截图。九个主资源的文件哈希互不相同。
- 专用区域图片处理：主图失败 → 对应区域SVG；SVG再失败 → 不依赖图片的主题渐变/图案/星形图标。区域名、非地图提示和来源说明可读；控制台记录区域、阶段和相对路径，不打印巨大base64串。
- 打包器支持JPEG/JPG、PNG、SVG、WebP、GIF。区域图片与首页图通过共享资产表内嵌一次，避免同一大图在配置和质量报告中重复编码；文件版保持普通相对路径。
- 质量页新增构建“区域背景图可用率”与“官方背景素材覆盖率”，同时显示本会话实际加载成功数。9/9可显示 **包含1张SVG占位**，不等于9/9官方实景；官方素材8/9=88.89%，其中一个为合并地区图。
- 装饰图片使用独立资产版本，不改变游戏图鉴/配方数据快照；构建时间戳不会制造新增套装。恢复分析引用时只复用完全一致的已存偏好快照，原历史文件不改，重新关联事件另行记录。人审50/100保留。
